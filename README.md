# WoW Forever Party Frames

Vanilla-style party portraits and attached bars, with numerical health/resources, recent HP history, visible auras, and named healing and buff presets. Separate healing/damage rates are not displayed.

Version **0.8.1** targets **WoW Forever 1.60.1**, interface **16001**. It repairs the noncasting cleanse controls by separating their secure actions from the native aura displays. Cleanse buttons remain visibly grey when idle; a matching removable effect adds full-color spell artwork, a timer and glow. Native debuff hover input is explicitly enabled, including combat tooltips. The existing bars, linked health-history settings, healing/buff presets and exact-rank casting remain. The [in-game checklist](tests/IN_GAME_CHECKLIST.md) separates actual client checks from simulated tests.

The frames float directly over the game with no enclosing window, border, or background. The existing bar style, colors, and status-bar texture are retained. The silver trim uses the larger native player-frame artwork, with mirrored endcaps and a stretched straight center. Portraits are 82 UI units, healing buttons 36×36, bars 174 units wide, and member frames 138 units apart. Bars and aura rows sit 12 units lower to fit health history below the member details. Debuffs and buffs occupy two rows below the bars. A compact information line sits under the name, with the preset below the portrait and a remote location below the buffs. The solo preview uses the same geometry and saved position as the live frames. Settings remain a separate panel.

## Install

Download the addon ZIP from the [latest GitHub release](https://github.com/Xyrces/WowForeverHealerPartyFrame/releases/latest), not GitHub's automatic source-code archive.

1. Close WoW or return to character selection.
2. Extract the downloaded `WowfPartyFrames-0.8.1.zip` into your Forever client's `Interface/AddOns` folder. The resulting path should be `Interface/AddOns/WowfPartyFrames/WowfPartyFrames.toc`, with no extra nested folder.
3. Enable **WoW Forever Party Frames** in the character-selection AddOns list and log in.
4. Enter `/wpf settings` to assign spells, or `/wpf test` while solo to inspect the noncasting preview. For an already-enabled installation updated on disk, enter `/reload` yourself to load the new files.

Install into your own WoW Forever client's `Interface/AddOns` folder. Creating the package does not install it into the game.

The repository includes [reconstructed release history](https://github.com/Xyrces/WowForeverHealerPartyFrame/blob/main/HISTORY.md) from twenty saved release packages, plus the current development tests and packaging tools. Historical snapshot commits are explicitly marked; they are not an original development-time Git log.

## Set up spells

Open **WoW Forever Party Frames** in the minimap's **AddOns** menu, or enter `/wpf`. Select a **preset**, select **Base**, **Shift**, **Ctrl**, or **Shift+Ctrl**, and drag spells into its four healing slots. Buffs are shared across those layers. The dropdown includes **New**, **Duplicate**, **Rename**, and **Delete** actions, a checkmark for the selection, and pages for longer lists. Name presets freely, such as Tank, Melee, or Caster. **Default** is always available and editable; it cannot be renamed or deleted. Fresh presets contain no assigned spells.

Use the exact rank you want from your spellbook: the addon saves that spell's ID instead of upgrading it to your highest rank. Different quadrants can contain different ranks of the same ability. Right-click a settings slot to clear it. Assignments save immediately and persist between sessions. Edits are locked during combat.

Under **Portrait controls**, choose **Buttons** for four full square icons on hover, or **Quadrants** to keep them inside the circular portrait. Both modes use the same sixteen assignments and positions. This display preference is saved and changes outside combat. The settings layer selects what you edit and what the solo preview demonstrates; live frames follow the modifier keys you hold.

Right-click a party member's frame, portrait healing quadrant, or buff button and choose **Assign preset**. The native menu retains its normal party actions, and the active preset is checked. The current preset appears below the portrait and in the frame/spell tooltip; the label adds no extra control. Editing a preset updates everyone using it. Deleting one returns affected members to Default.

New party members receive Default. If you previously assigned another preset to that character, a small prompt offers **Confirm (10s)** or **Keep Default**. Timeout or dismissal keeps Default without forgetting the previous choice; explicitly selecting Default in the context menu does remember that choice. Each visible prompt has its own ten-second window, paused during combat and loading screens. Reordering the party or using `/reload` preserves current assignments and any remaining confirmation time. New logins and genuine rejoins offer remembered choices again. Remembered choices are separate for each of your characters and identify recipients by GUID, with realm-qualified names as a fallback. No messages are sent to party chat.

## Use the frames

**Debuff removal:** open **Debuff removal...** in `/wpf`. Magic, Disease, Poison, and Curse slots automatically suggest supported spells that your own character has learned. Drop a different learned removal spell or rank to override one type; right-click to disable it; its **Auto** button restores automatic selection. For priests, automatic Disease selection prefers Cure Disease when learned, with Abolish Disease available as a manual choice. These choices are saved separately for each of your characters and apply across every recipient preset. Paladin spells covering multiple selected types use one action button. Pet abilities are not included.

The 36px cleanse buttons sit just right of the portrait. Every assigned action stays visible and clickable, in and out of combat: its spell icon is dark grey while idle, then full color with a timer, type border and glow when the client reports a matching harmful effect you can dispel. Grey indicates no matching alert, not a disabled action. There are no invisible idle casting areas. Left-click casts the assigned exact rank on that member without changing the selected target; right-click opens the member menu. The separate debuff row retains native effect tooltips; hovering a cleanse button describes its removal spell. Existing keyboard bindings and portrait modifier layers are unchanged. A removable debuff indicates spell capability, not a guarantee of range, mana, cooldown readiness, or which same-type effect the spell will remove.

**Cleanse implementation and verification:** secure actions are direct children of the ordinary party frame, following its current unit token. The native alert is a separate mouse-transparent display; its visibility changes only artwork, never the action or click area. This replaces the 0.8.0 native-child design that displayed alerts but did not cast. Setup/configuration failures hide and disarm partially configured buttons. `/wpf status` reports setup problems. `/wpf test` shows noncasting grey/active examples using configured removal actions. Offline checks verify separation, exact assignments, roster changes and failure cleanup; actual combat casting and hover behavior still require client confirmation.

**Health-history settings:** edit either **Step (sec)** or **Total (sec)** in `/wpf` and press Enter or leave the field. Both values stay linked through the twelve visible samples. The minimum/default is **0.25 sec per sample / 3 sec total**; for example, 0.5 sec means 6 sec total, and setting 10 sec total uses 10/12 sec per sample. Fractional values are retained even if the displayed number is rounded. Invalid values and combat edits are refused. Changing the duration starts a fresh live history, retains the strip's size, and refreshes the synthetic preview. Live history remains combat-only and the 2px mouseover preview still works outside combat.

- **Health history:** visible only while you are in combat, with a fresh history each fight. Twelve horizontal 1px snapshots share the health bar's width, newest at the bottom touching its trim. Each represents actual HP as a fraction of max HP at sampling time; older rows fade. Colors smoothly pass through green at 90–100%, yellow at 70%, orange at 45%, and red at 15%. The client evaluates the color curve and fills directly from protected values; addon code never calculates a health difference or infers incoming rates. History follows the secure frame's named-member binding through unit-token changes, using its cached public roster identity when GUIDs are protected. A readable GUID mismatch, an unresolved binding, disappearance/disconnection, or world unload clears history. Brief sampling stalls leave blank missed rows; gaps as long as the selected total history start fresh instead of inventing samples. If native color curves are unavailable, history uses a uniform subdued green; `/wpf status` reports that fallback and the selected step/window. The explicit solo preview still shows synthetic history for inspection outside combat.
- **Portraits and bars:** four floating party-member frames replace the native party frames, with class-colored names and numerical current/maximum health and resources. Their starting position follows the native party frame position; a custom position is preserved.
- **Health indicators:** brighter incoming-heal fill shows your pending healing; a darker green fill shows others' pending healing. Native patterned shields follow the incoming heals, with a right-edge glow when the shield exceeds the available bar space, including at full health. Healing absorption covers the affected portion of current health and has a left-edge overflow glow. The client's native calculator reduces incoming healing and healing absorption against each other and clamps the display inside the existing health bar. Health numbers remain current HP, not predicted HP. These are current/predicted amounts, not per-second rates. Indicators refresh on health/prediction events and with the regular display update, follow combat party reordering, and clear on missing members, loading, or failed reads. `/wpf status` reports availability separately from combat rates. The solo preview demonstrates incoming heals plus a shield, a full-health shield glow, healing absorption, and another healer's incoming heal with no heal from you.
- **Healing:** hover over a portrait to reveal four healing buttons. Hold Shift, Ctrl, or both to select another group of four; the icons, ranks, and open tooltip update immediately. Click a configured button to cast that exact rank directly on the member without changing your current target. Empty slots do nothing, including an empty Base slot; Alt combinations also do nothing on healing controls. Left-click the name or bars to target normally. Spell tooltips open outside the party stack.
- **Minimum-heal preview:** hovering an assigned healing button adds a 2 UI pixel strip touching the top of the existing health trim. Solid bright green shows minimum direct healing from the current HP endpoint; segmented green adds the spell's full HoT amount; patterned pale blue shows shield capacity from the left, including at full health. The strip clips at the health-bar edges and disappears on pointer leave. It follows the displayed rank and modifier layer, with amounts also written in the tooltip. It uses supported public English spell descriptions cached outside combat, without target reductions, crits, or protected-health arithmetic. It is a planning estimate, not a guarantee of received healing. The HoT amount covers its full duration, not the remaining ticks of an existing HoT. Unsupported, ambiguous, or unavailable descriptions produce no preview; ordinary spell tooltips and casts remain available. Equipment/spell changes refresh the cache outside combat, and the last cached minimum remains available through combat until that refresh.
- **Already-active healing effects:** on live party frames, assigned healing buttons show a green top edge/check and native remaining-time text when their corresponding helpful aura is active. All four modifier layers are tracked, using known same-name ranks and any caster. The exact assigned icon, rank, and cast remain unchanged; intentional refresh clicks are allowed. Native aura slots own matching and timers, including in combat. The solo sample preview cannot show real active effects, and clients without the native aura API omit these indicators. Existing assigned Buffs slots continue using their combined active/reapply display.
- **Member details:** level, localized class, and assigned role text appear under the name, followed immediately by the role icon and any skull/star/moon party marker. Neither assignment is inferred from class or preset. Roles mirror the native party frames' assignment API, which does not report whether a human manually selected the assignment. Missing roles show neither role text nor icon; missing markers show no icon. Offline/Dead stays on the name line. The selected preset appears below the portrait; hover the frame for its full name. A location appears only when public map data establishes a different zone or dungeon. Floors in the same dungeon and submaps in the same zone share a location; a dungeon remains distinct from its outdoor zone. Unavailable details are omitted. Labels refresh once per second and immediately when their unit, preset, or party marker changes. Solo preview does not invent assigned roles or markers.
- **Buffs:** configured spells appear consecutively in one Buffs row. Removing an assignment outside combat closes the gap; ordinary aura expiry keeps the button in place for reapplication. An active native aura covers its reapply button with the icon, timer, and stacks; when absent, the same slot shows the assigned spell with a `+`. Left-click always casts the assigned exact rank on that member without changing your selected target; right-click opens their native menu, including preset assignment. Known spellbook ranks with the same localized name count as one buff family for display, without changing the casting rank. Other active helpful auras fill the remaining slots after the last configured buff, excluding those families. The row holds eight icons total. Cached public spell metadata retains known icons when later API responses are unavailable. On clients lacking native containers, configured buffs use public reads and show `?` for unknown status.
- **Debuffs:** harmful effects remain visible without targeting the member. The native container renders icons, timers, and stacks inside the client without exposing aura data to the addon. Both aura rows follow the frame's current unit, including combat party reordering. A compatibility fallback uses permitted public aura reads when the native container API is unavailable; it cannot display data the client completely withholds. `/wpf status` reports which renderer is active. Readable Weakened Soul is prioritized in the fallback.
- **Rates:** the healing/damage/net bar is currently omitted, including its unavailable-data placeholder and tooltip. The existing public-feed calculation remains available internally for future work; `/wpf status` still reports feed availability. Native health indicators show current or predicted amounts, not rolling rates.

Existing member assignments stay attached to their names when the party order changes during combat. New members arriving during combat are configured after combat ends.

Modifier actions are configured through the client's secure click buttons before combat. No global keyboard bindings are installed or changed. Self/focus/mouseover-cast modifiers cannot redirect these buttons away from their party member; right-click still opens that member's native menu with any modifier. Buff clicks retain their existing behavior across modifiers. Other click-casting addons should not register or modify these same buttons; overlapping addons cannot be guaranteed to coexist.

## Commands

| Command | Action |
| --- | --- |
| `/wpf settings` | Open presets, spells, debuff removal, and linked history settings. |
| `/wpf unlock` | Allow moving the party frames outside combat. |
| `/wpf lock` | Lock their position. |
| `/wpf reset` | Move to the native party frame position. |
| `/wpf test` | While solo, toggle a noncasting preview at the live frame position. |
| `/wpf status` | Show addon and data-availability status. |
| `/wpf blizzard` | Toggle the native party frames; this choice is saved. |

Native party frames are hidden only after the replacement frames initialize successfully. Use `/wpf blizzard` outside combat to show them again if needed.

The game's native party-control drawer for markers such as star, moon, and skull remains untouched. It appears when you are in a real group; a solo `/wpf test` preview does not create a group or open that drawer.

Unlocking reveals a small text handle above the frames. Drag it and release to apply the new position, then lock it again. The preview uses class icons instead of character portraits, shows the exact preset selected in settings (including empty slots), and closes when you join a group. Live frames show the actual party members' portraits and assigned presets. Right-click assignment and remembered-player prompts require a real party.

## Validation

Off-client Lua tests cover calculations, aura handling, saved profiles, and spell assignment. They cannot establish the appearance or protected casting behavior of the actual game client. Complete the [in-game checklist](tests/IN_GAME_CHECKLIST.md) before relying on this build in a dungeon.

## Developer validation

From the source repository, use Python 3.10 or newer:

```text
python -m pip install -r requirements-test.txt
python tests/run_tests.py
python tools/package.py
```

Tests use Lupa's Lua 5.1 runtime. The packaging script uses only the Python standard library, verifies the TOC file list and archive checksums, and writes the addon ZIP plus a `.zip.sha256` file under `dist`. It includes only the addon and user documentation, and does not install anything into the game.
